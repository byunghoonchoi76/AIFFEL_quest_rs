## 5. Fine-tuning 추가 실험

### 5-1. 실험 배경

- 5 epoch 학습 후 skeleton 시각화 품질이 부정확함을 확인
- epoch 30~50까지 늘릴 시간 부족
- ResNet50 best model (epoch5, val=0.2817)에서 이어서 학습하는 방식 선택

### 5-2. Fine-tuning 설정

| 항목 | 값 |
|---|---|
| 기반 모델 | ResNet50 epoch5 best (val=0.2817) |
| 추가 Epochs | 10 |
| Learning Rate | 0.0001 (기존 0.0007 → 낮춤) |
| LR 낮춘 이유 | 수렴된 가중치를 크게 흔들지 않기 위함 |

### 5-3. Fine-tuning Epoch별 결과

| Epoch | Train Loss | Val Loss |
|:---:|:---:|:---:|
| 1 | 0.2555 | 0.2696 |
| 2 | 0.2469 | **0.2693 ← Best** |
| 3 | 0.2399 | 0.2696 |
| 4 | 0.2324 | 0.2713 |
| 5 | 0.2215 | 0.2753 |
| 6 | 0.2340 | 0.2713 |
| 7 | 0.2300 | 0.2717 |
| 8 | 0.2264 | 0.2726 |
| 9 | 0.2227 | 0.2735 |
| 10 | 0.2189 | 0.2756 |

### 5-4. Fine-tuning 분석

- epoch 2에서 val loss 0.2693으로 최저점 달성 후 상승 → **과적합 시작**
- train loss는 계속 감소하지만 val loss는 반등 → early stopping이 필요했던 구간
- fine-tuning은 2 epoch 정도만 해도 충분했음

## 7. 분석 및 결론

### 7-1. Backbone 깊이에 따른 경향

- backbone이 깊어질수록 val loss 감소 (ResNet50 → 101 → 152 순으로 성능 ↑)
- 단, 파라미터 대비 성능 향상폭은 크지 않음
  - ResNet101: 파라미터 +55.9% → val loss 고작 -0.0018 개선
  - ResNet152: 파라미터 +101.9% → val loss 고작 -0.0031 개선
- 실용적 측면에서 ResNet50 대비 ResNet101/152의 이점이 미미함

### 7-2. 핵심 시사점

```
backbone을 깊게 바꾸는 것보다 (ResNet50 → 152: -0.0031)
같은 모델을 더 학습시키는 게 더 효과적 (Fine-tuning: -0.0124)

→ 이번 실험에서는 "학습량 > backbone 깊이"
→ 단, 더 많은 epoch 학습 시 결과가 달라질 수 있음
```

### 7-3. Skeleton 시각화 품질

- 세 모델 모두 관절 포인트를 정확히 잡지 못하는 현상 확인
- 원인: **학습 부족 (5 epoch)**
  - loss가 0.27~0.28 수준으로 아직 수렴 중인 상태
  - epoch 수를 늘리면 시각화 품질 개선 예상

### 7-4. 효율성 관점 요약

| 모델 | 성능 | 파라미터 효율 | 추천 상황 |
|---|---|---|---|
| ResNet50 | 보통 | **최우수** | 빠른 실험, 경량 배포 |
| ResNet101 | 중간 | 중간 | 성능/속도 균형 필요 시 |
| ResNet152 | **최고** | 낮음 | 성능 최우선, 자원 충분 시 |
| ResNet50 Fine-tuned | **최고** | **최우수** | 충분한 학습 시간 있을 때 |
