## 1. 프로젝트 개요

### 학습 목표
- Transformer(Encoder-Decoder) 구조를 직접 구현하여 한국어 챗봇 학습


## 5. 트러블슈팅 — 주요 문제 3가지

### 🔴 문제 1: MeCab + SentencePiece 중복 적용 → Vocab 붕괴

**발생 버전:** v1 ~ v12

**증상**
- 모든 답변이 `⁇ ⁇ ⁇` (UNK 토큰) 또는 빈 문자열
- BLEU Score ≈ 0.000

**원인**
```
[잘못된 파이프라인]
문장
→ MeCab 형태소 분석: ['하루', '가', '또', '가', '네요']
→ " ".join() → "하루 가 또 가 네요"
→ SentencePiece encode_as_ids()
→ piece_to_id('하루') = 3 (UNK!) ← SentencePiece vocab에 없음
→ 학습 데이터 대부분 UNK ID → 모델이 UNK만 학습
→ 출력도 ⁇⁇⁇ 범람
```

**해결**
```
[올바른 파이프라인]
문장
→ MeCab 형태소 분석: ['하루', '가', '또', '가', '네요']
→ word2idx.get('하루') = 264 ← 직접 형태소 단위 매핑
→ [264, 9, 136, 9, 451, ...] ← 정확한 ID 변환
```

---

### 🔴 문제 2: label_smoothing + ignore_index 동시 사용 → Loss Scale 폭발

**발생 버전:** v1 ~ v14 (SentencePiece 사용 버전 포함)

**증상**
- Epoch 1 Loss = **2,865 ~ 3,511** (정상값 `ln(4000)≈8.3`의 400배!)
- 50에폭 후에도 Loss 10~30대에서 수렴 실패
- 모든 질문에 동일한 짧은 답변

**원인**
```python
# 문제 코드
F.cross_entropy(
    pred, gold,
    ignore_index=0,        # PAD 제외 의도
    reduction='mean',
    label_smoothing=0.1    # ← PyTorch 2.x에서 문제 발생
)
# PyTorch 2.x 동작:
# ignore_index로 제외된 PAD 위치도 smoothing 계산에 포함
# → loss scale 비정상 폭발 → gradient 왜곡 → 학습 실패
```

**해결**
```python
# 수정 코드 - label_smoothing 제거
F.cross_entropy(
    pred, gold,
    ignore_index=0,   # PAD(0) 위치 제외
    reduction='mean'  # 유효 토큰 평균 → 2~8 범위 정상
)
# 결과: Epoch 1 Loss = 6.9 (정상) → Epoch 47 = 0.28 (수렴)
```

### 🔴 문제 3: EOS를 생성 차단 토큰에 포함 → 답변 종료 불가

**발생 버전:** v12 ~ v14

**증상**
- 답변이 빈 문자열
- 또는 `max_len(30)`까지 무의미한 토큰 연속 출력

**원인**
```python
# 문제 코드
_skip = {PAD_ID, UNK_ID, START_ID, END_ID}  # ← EOS도 포함!

for sid in _skip:
    logits[sid] = float('-inf')   # EOS 선택 불가 → 종료 불가

if next_id == END_ID:             # 절대 도달 불가
    break                         # → 빈 답변 또는 무한 반복
```

**해결**
```python
# 수정 코드
logits[[PAD_ID, UNK_ID]] = float('-inf')  # PAD/UNK만 차단

if step < min_len:                # 최소 길이(2) 이후만
    logits[EOS_ID] = float('-inf')

if next_id == EOS_ID:             # 정상 종료 가능
    break
```

### 기타 문제들

| 문제 | 원인 | 해결 |
|------|------|------|
| 인코더 입력에 BOS/EOS 포함 | `set_encode_extra_options('bos:eos')` 적용 후 enc/dec 구분 없이 인코딩 | enc: BOS/EOS 없음, dec만 포함 |
| LR Warmup 미작동 | 에폭 단위 LR 업데이트 → 실제 step 수 부족 | 배치 단위 `global_step` 카운터로 변경 |
| 한글 폰트 깨짐 | apt-get 미작동 환경 + matplotlib 캐시 문제 | GitHub에서 NanumGothic.ttf 직접 다운로드 |
| ko.bin Word2Vec 로드 실패 | gensim 4.x에서 3.x 저장 파일 구조 불일치 | EDA 증강으로 대체 (뉘앙스 보존에 더 적합) |

## 8. 결론 및 회고

### 잘 된 점
- MeCab 단독 + 커스텀 Vocab 구조가 가장 안정적임을 실험으로 증명
- EDA 증강이 챗봇 데이터의 뉘앙스를 유지하면서도 3만개 달성
- label_smoothing + ignore_index 조합이 PyTorch 2.x에서 loss를 폭발시킨다는 이슈 직접 발견

### 개선 가능한 점
- 형태소 단위 출력이어서 "다른 생각 을 해 보 세요" 처럼 공백이 붙는 문제 → 후처리 필요
- ko.bin Word2Vec 로드 성공 시 유사어 대체 증강으로 품질 추가 향상 가능
- D_FF=1024로 늘린 것이 최종 성능 향상에 기여 (이전 512 대비)
