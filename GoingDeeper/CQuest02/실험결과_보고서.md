## 2. 실험별 학습 설정

### 실험 ① RetinaNet + ResNet50

```
backbone  : ResNet50 (ImageNet 사전학습)
neck      : FPN (P3~P7, 각 256ch)
head      : Classification Subnet (KA=72ch) + Box Subnet (4A=36ch)
anchor    : aspect_ratios=[0.5,1.0,2.0] × scales=[1.0, 2^1/3, 2^2/3] = 9개/위치
            P3~P7 전체 ~92,000개 앵커
loss      : Focal Loss (α=0.25, γ=2.0) + Smooth L1
optimizer : Adam (lr=1e-4)
scheduler : ReduceLROnPlateau (patience=3, factor=0.5)
batch     : 2 / img_size : 384×640 / epochs : 5
```

### 실험 ② YOLOv8s + CSPDarknet

```
backbone  : CSPDarknet (ImageNet 사전학습, YOLOv8 기본)
neck      : PANet + FPN
head      : Detect (Anchor-free)
loss      : BCE (분류) + CIoU (bbox 회귀)
library   : ultralytics 8.4.46
batch     : 4 / imgsz : 640 / epochs : 5
workers   : 0 (Bus error 방지)
```

**KITTI → YOLO 형식 변환:**
```
KITTI: [x_min, y_min, x_max, y_max] (픽셀 절대좌표)
          ↓ 변환
YOLO:  [cx, cy, w, h] (0~1 정규화)
cx = (x_min + x_max) / 2 / image_width
cy = (y_min + y_max) / 2 / image_height
```

### 실험 ③ YOLOv8s + ResNet50 (가설 2 검증)

**백본 교체 이유:**
- YOLOv8 기본 백본인 CSPDarknet 대신 ResNet50으로 교체
- 백본만 바꿨을 때 성능 변화를 측정 → 아키텍처 vs 백본 영향 분리 분석
- RetinaNet과 동일한 ResNet50 백본 사용 → 순수 아키텍처 차이 비교 가능

**단계적 학습 전략 (총 8 epochs):**
```
[단계 1] epochs=3, freeze=10, lr=0.001
  → 백본(ResNet50) 고정
  → neck+head만 학습 (새 백본 feature에 빠르게 적응)
  → mAP 결과: 0.55 → 0.70

[단계 2] epochs=5, freeze=0, lr=0.0001
  → 전체 레이어 fine-tuning
  → 더 낮은 학습률로 안정적 수렴
  → mAP 결과: 0.70 → 0.82 (그래프 기준)
  → 총 학습: 3+5 = 8 epochs (② CSP의 5 epochs보다 많음)

왜 단계적 학습이 필요한가?
  처음부터 전체 학습 시 → neck과 새 백본 feature 불일치로 불안정
  단계 1에서 neck이 먼저 적응 → 단계 2에서 안정적으로 전체 최적화
```

**ChannelAdapter (채널 변환 모듈):**
```
ResNet50 출력 채널 → YOLOv8 기대 채널로 변환
  C3: 512ch  → 256ch (1×1 Conv + BatchNorm + SiLU)
  C4: 1024ch → 512ch (1×1 Conv + BatchNorm + SiLU)
  C5: 2048ch → 512ch (1×1 Conv + BatchNorm + SiLU)

왜 필요한가?
  ResNet50은 YOLOv8용으로 설계되지 않아 채널 수가 다름
  → 1×1 Conv로 채널 수를 맞춰줘야 neck(PANet)에 연결 가능
```

**학습 설정:**
```
batch : 4 / imgsz : 640 (단계 2는 480으로 축소, 시간 단축)
device: GPU (Tesla T4)
workers: 0 (Bus error 방지)
```

## 5. 가설 검증 결과

### 가설 1: YOLOv8이 속도↑ 정확도↓

| 구분 | 예상 | 실제 | 판정 |
|------|:----:|:----:|:----:|
| 속도 | YOLOv8 빠름 | 46.25 vs 12.01 FPS (3.9배) | ✅ 일치 |
| 정확도 | YOLOv8 낮음 | 0.774 vs 0.564 (YOLOv8 더 높음!) | ❌ 불일치 |

**불일치 원인:**
1. Anchor-free가 KITTI 가로로 긴 이미지에 더 효과적
2. ultralytics 내장 증강(Mosaic, MixUp)이 더 다양함
3. RetinaNet epochs=5 학습 부족 가능성

### 가설 2: ResNet50 교체 시 mAP↑ FPS↓

| 구분 | 예상 | 실제 | 판정 |
|------|:----:|:----:|:----:|
| mAP | RN50 더 높음 | CSP(0.774) > RN50(0.658) | ❌ 불일치 |
| FPS | RN50 더 낮음 | CSP(46.25) ≈ RN50(46.41) | ❌ 불일치 |

**불일치 원인:**
- YOLOv8 neck(PANet)이 CSPDarknet에 맞게 최적화 설계됨
- 그러나 **학습 곡선에서는 RN50이 더 높음** (conf threshold 차이)
- 동일 conf=0.001로 재측정 시 결과 역전 가능성 있음

> 💡 **추가 발견**: Pedestrian AP 0.09 → 0.66 (7.2배 개선!)
> → YOLOv8 구조 자체가 Pedestrian 감지에 훨씬 유리

### 가설 3: Pedestrian AP < Car AP

| 클래스 | AP@0.5 |
|--------|:------:|
| Car | 0.8150 |
| Pedestrian | **0.0909** |
| 격차 | **0.7241 (8.9배)** |

✅ **가설 일치** - 예상보다 격차가 훨씬 큼

**원인:**
- Class Imbalance: KITTI에서 Car >> Pedestrian 샘플 수
- Bbox 크기: 보행자 bbox가 작아 앵커 매칭 어려움
- Occlusion: 보행자가 가려지는 경우 많음

| FPN P2 레벨 추가 | 🟢 낮음 | 더 작은 물체 감지 |
